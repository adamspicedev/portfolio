# Story Studio image uploads

Story Studio accepts still JPEG, PNG and WebP covers up to 3 MiB and 25 million decoded pixels. Select **Upload cover**, wait for confirmation, describe the image, then save the story. Existing local or HTTPS cover URLs still work. Uploading does not save or publish a story. Uploaded files are public to anyone with their URL even while the story is a draft.

The `/api/story-images` POST route checks the request origin and existing Clerk CMS administrator allowlist before reading a bounded multipart body. Sharp fully decodes and re-encodes images as WebP, applies orientation, removes metadata, limits the longest side to 2400 pixels, and rejects malformed or animated content. UUID filenames prevent collisions and do not retain original filenames. Vercel Blob stores immutable images durably; the server never persists uploads to local disk. Existing covers are never overwritten or deleted when selecting a replacement. Discarded selections may leave unused public images; remove these through the Blob dashboard only after confirming that no story references them.

Production uses the dedicated public `portfolio-story-images` Blob store, Sydney region, connected only to the portfolio project's Production environment. The integration manages server-only access configuration. Do not copy tokens into client code or source control. New deployments receive the connection configuration automatically. Without storage configuration, the upload endpoint fails clearly and existing URL entry remains usable.

The account was verified as active Hobby when connected. Hobby limits stop Blob access instead of charging overages; a future move to Pro changes the billing model and must be reviewed separately. No plan upgrade is required by this feature.

Unit tests cover image bytes, authorization, bounded requests, safe errors, and real SQLite restart persistence/social metadata for uploaded URLs. Browser tests cover the uploader component with controlled HTTP responses and an isolated draft fixture; the fixture's save uses localStorage, not the production CMS. The production-browser suite separately verifies that unsigned/cross-origin upload requests cannot bypass authorization. Live signed-in upload/save/reload should be verified using a private test draft, never an existing published story. Image uploads themselves are public even for test drafts.
